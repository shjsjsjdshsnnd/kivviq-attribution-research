# Step 3.11 Baseline Validation Design

## Scope

Step 3.11 adds a public, versioned validation library under `src/validation/` and a reusable test suite under `tests/validation/`. The library validates frozen operator evidence; it does not change operator policy logic, the Step 2 Action Ontology, simulator semantics, Step 3.1 metrics, or the Step 3.10 interface.

The validation library owns PASS/FAIL decisions and machine-readable reports. Operators continue to receive only `CanonicalOperatorInputV2` and return `CanonicalOperatorDecisionV2`.

## Dependency boundary

The permitted dependency direction is:

```text
validation and evaluation
  -> canonical operator interface
  -> frozen operators
```

`src/validation/` may inspect evaluator artifacts, operator metadata, canonical inputs and decisions, Action Ontology validation results, constraint dispositions, replay evidence, and test-only hidden-world witnesses. It must never copy hidden data into an operator input.

The dependency-cruiser configuration will reject imports from operator-facing modules into `src/validation/`. The package root remains operator-safe and does not export validation. A new `./validation` package subpath provides the evaluator-owned public API.

## Module layout

The implementation uses focused modules:

- `version.ts`: suite, contract, report, fixture, and seed-set schema versions plus the frozen Step 3.10 parent commit.
- `contract.ts`: the validation contract, required check identifiers, frozen semantics, and independently recomputed contract fingerprint.
- `seed-sets.ts`: deterministic multi-world seed cases and their fingerprint.
- `fixtures.ts`: frozen validation fixture descriptors and their fingerprint. Tests provide executable observations and worlds while the library owns their semantic manifest.
- `determinism.ts`: canonical decision and full-run comparison, seed completeness, uncontrolled-randomness evidence, and deterministic tie/replay checks.
- `leakage.ts`: hidden-truth and prohibited-information invariance checks over paired canonical inputs and decisions.
- `temporal-boundaries.ts`: event-time and legal-lookback validation, including exact inclusive/exclusive boundary semantics.
- `action-conformance.ts`: canonical decision-envelope, Action Ontology, action ordering, duplicates, conflicts, and malformed-output checks.
- `constraint-conformance.ts`: deterministic verification of accepted, rejected, and modified evaluator dispositions without granting operators execution authority.
- `replay.ts`: reconstruction and comparison of decisions from recorded canonical inputs and operator identity.
- `provenance.ts`: independent recomputation of contract, observation, legal-action-space, input, decision, operator, fixture, seed-set, and report fingerprints.
- `conformance.ts`: aggregation of evidence into the required check results for one operator.
- `report.ts`: immutable machine-readable report schema, report creation, validation, canonical serialization, and fingerprinting.
- `harness.ts`: registry-driven orchestration across every frozen operator with fail-closed handling for missing evidence.
- `index.ts`: evaluator-facing public exports.

## Validation contract

The contract freezes the checks required for every baseline:

- determinism
- seed reproducibility
- hidden-truth isolation
- future-information isolation
- temporal and lookback legality
- Action Ontology conformance
- constraint conformance
- frozen policy semantics
- permitted-information sensitivity
- prohibited-information invariance
- missing-data behavior
- zero- and multi-Action handling
- artifact replay
- provenance integrity
- uncontrolled-randomness detection
- operator isolation from evaluator and simulator authority

Each check returns `PASS` or `FAIL`, structured evidence fingerprints, and deterministic issue codes. The harness fails a baseline when required evidence is absent, malformed, internally inconsistent, or cannot be independently recomputed.

## Evidence and report flow

Tests construct canonical inputs through evaluator-owned Step 3.10 builders and execute frozen operators through `invokeOperatorAtDecision`. They supply the resulting evidence to the Step 3.11 harness.

The harness recomputes fingerprints from canonical values, compares repeated decisions and runs, validates Actions and dispositions, checks paired leakage cases, checks temporal windows, and replays recorded decisions. It then emits an immutable report containing:

- operator ID and version
- implementation and configuration fingerprints
- validation suite, fixture, and seed-set versions and fingerprints
- one result for every required check
- overall `PASS` or `FAIL`
- evidence fingerprint
- report fingerprint

Report generation excludes timestamps and ambient process data so identical evidence produces byte-identical canonical JSON and the same report fingerprint.

## Frozen baseline registry

The Step 3.11 test registry includes all 27 operators frozen through Step 3.10:

- DO_NOTHING and STATUS_QUO
- five advertising heuristics
- four inventory heuristics
- four pricing and promotion heuristics
- three merchandising heuristics
- three greedy operators
- six flawed optimizers

The registry records each operator's frozen identity and family-specific evidence callbacks. The shared harness runs common checks. Targeted semantic tests continue to prove each policy's permitted sensitivity, prohibited invariance, tie breaking, missing-data behavior, and characteristic decision rule.

## Test strategy

Tests live under `tests/validation/` and import validation semantics from `src/validation/`.

1. Contract and report tests first prove versioning, stable serialization, fingerprint recomputation, fail-closed behavior, and tamper rejection.
2. Shared harness tests run every frozen operator across fixed seeds and multiple canonical fixture variants.
3. Leakage tests pair identical operator-visible inputs with different hidden truth and future witnesses, then require identical decisions.
4. Temporal tests reject future events and exclude observations outside each legal lookback window.
5. Action and constraint tests cover malformed Actions plus accepted, rejected, and modified dispositions for single and multi-Action decisions.
6. Replay tests rebuild decisions and complete evaluation evidence from recorded artifacts.
7. Family-specific tests assert frozen policy semantics, permitted sensitivity, prohibited invariance, deterministic ties, and missing-data fallbacks.
8. Deterministic generated cases exercise thresholds, observation combinations, worlds, and seeds without adding an uncontrolled property-testing dependency.
9. Architecture, typecheck, focused Step 3.11 tests, all inherited operator tests, the full suite, and build form the freeze gate.

## Error handling

Public validation functions return typed check results for expected conformance failures and throw `BaselineValidationError` only for malformed API use or invalid contract/report structures. The harness converts missing or unverifiable required evidence into deterministic `FAIL` results. It never repairs operator output, fabricates evidence, or silently downgrades a required check.

## Freeze artifacts

Step 3.11 freezes:

- the validation suite semantic version
- validation contract and schema fingerprints
- report schema and canonical serialization
- fixture manifest and seed-set versions and fingerprints
- required check identifiers and PASS/FAIL rules
- the complete 27-operator registry
- leakage, temporal, Action, constraint, replay, and provenance test semantics
- the Step 3.10 parent commit and dependency versions

The final Step 3.11 document records the exact commit, commands, test counts, fingerprints, and known limitations. Any substantive change requires a new validation-suite version.
